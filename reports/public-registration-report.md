## 1. ملخص تنفيذي (Executive Summary)

تم بنجاح بناء وتفعيل ميزة **التسجيل الذاتي العام (Public Self-Registration)** عبر الـ Backend والـ Frontend، والتي تمكّن أي مستخدم جديد من تنزيل التطبيق وفتح حساب شبكة مستقلة جديدة بالكامل دون الحاجة إلى تدخل يدوي من مدير النظام.
- يقوم النظام بإنشاء كيان مستأجر جديد (`Tenant`) باسم الشبكة المطلوب مع توليد معرف رابط فريد (`slug`) غير قابل للتكرار ومحمي ضد التعارضات.
- يتم إعطاء الشبكة الجديدة تلقائياً فترة تجريبية مجانية لمدة 7 أيام (`TRIAL`) مع سقف راوترات افتراضي (`maxRoutersLimit = 2`).
- يتم إنشاء حساب المشرف الأول للشبكة بدور `TENANT_ADMIN` وتشفير كلمة المرور وتوثيق العملية في سجل التدقيق الأمني (`AuditLog`).
- يتم إصدار رمز JWT مباشرة لإتمام تسجيل الدخول التلقائي فور إنشاء الحساب، وينتقل التطبيق مباشرة إلى لوحة التحكم (`DashboardScreen`) في حالتها الجديدة النظيفة.

## 2. تفاصيل التطوير في الـ Backend (`mikrotik_cards_backend`)

### أ. حالة الاستخدام (`src/application/use-cases/auth/RegisterTenantUseCase.ts`):
- **التحقق الشامل من التفرد (Global Uniqueness Check):**
  - فحص اسم المستخدم `username` عبر كامل النظام للتأكد من عدم وجوده في أي Tenant سابق (حيث يتم الدخول باسم المستخدم مباشرة).
  - فحص البريد الإلكتروني `email` عبر كامل النظام للتأكد من عدم تسجيله مسبقاً.
  - إرجاع خطأ نزاع `409 Conflict` مع رسائل عربية واضحة في حال التكرار.
- **توليد الـ Slug الفريد (Collision-Free Slug):**
  - خوارزمية استخراج الاسم بالحروف اللاتينية والأرقام مع إضافة لاحقة عشوائية فريدة (Hex Random Bytes).
  - فحص وجود الـ Slug في قاعدة البيانات لضمان عدم حدوث أي تعارض نهائياً.
- **الإنشاء المتكامل والذري (`prisma.$transaction`):**
  - إنشاء الـ `Tenant`: الاسم، الـ slug، العملة الافتراضية SDG، الحالة ACTIVE، حالة الاشتراك TRIAL، تاريخ انتهاء التجربة (الآن + 7 أيام)، وسقف راوترات 2.
  - إنشاء الـ `User`: مرتبط بالـ tenant، برتبة `TENANT_ADMIN`، كلمة مرور مشفرة بـ bcrypt، وحالة ACTIVE.
- **سجل التدقيق الأمني (`AuditLogger`):**
  - تسجيل قيد تدقيق (`CREATE` على كيان `Tenant`) يوثق تاريخ واسم الشبكة والمشرف.
- **إصدار التوكن والولوج الفوري:**
  - توليد رمز JWT يحمل `userId`, `tenantId`, `role` لتسجيل الدخول التلقائي المباشر.

### ب. التحقق من المدخلات (`src/presentation/validators/register.validator.ts`):
- مخطط Zod صارم يتحقق من:
  - اسم الشبكة (2 إلى 100 حرف).
  - الاسم الكامل للمدير (2 إلى 100 حرف).
  - اسم المستخدم (3 إلى 50 حرف، بأحرف وأرقام ورموز مسموحة).
  - البريد الإلكتروني (صيغة Email قياسية صالحة، تحويل للأحرف الصغيرة).
  - كلمة المرور (8 أحرف على الأقل).
  - رقم الهاتف (اختياري).

### ج. مسار الـ API العام (`src/presentation/http/routes/auth.routes.ts`):
- مسار `POST /api/v1/auth/register`: مسار عام مفتوح بدون `authMiddleware`.
- يعيد HTTP `201 Created` عند النجاح مع التوكن ومعلومات المستأجر والمستخدم.
- يعيد HTTP `400` عند أخطاء التحقق من الحقول و HTTP `409` عند تكرار اسم المستخدم أو البريد.

### د. اختبارات التكامل (`tests/presentation/RegisterRoutes.test.ts`):
- اختبار التسجيل الناجح والتحقق من صحة بيانات الـ Tenant والـ User وفترة الـ 7 أيام وسجل التدقيق وإصدار التوكن.
- اختبار رفض تكرار اسم المستخدم عبر النظام بـ 409.
- اختبار رفض تكرار البريد الإلكتروني بـ 409.
- اختبار رفض كلمات المرور الأقل من 8 أحرف بـ 400.
- اختبار رفض صيغ البريد غير الصالحة بـ 400.

## 3. تفاصيل التطوير في الـ Frontend (`mikrotik_cards_app`)

### أ. تحديث عميل الـ API (`lib/services/api_client.dart`):
- إضافة دالة `ApiClient.registerTenant(...)` التي تقوم بإرسال طلب التسجيل وتخزين التوكن في الذاكرة وفي `SharedPreferences` تلقائياً فور النجاح.

### ب. شاشة التسجيل الذاتي (`lib/screens/register_screen.dart`):
- واجهة نيومورفيك متناسقة مع الهوية البصرية للتطبيق والخط العربي (Cairo).
- حقول إدخال واضحة:
  1. اسم الشبكة / الشركة.
  2. الاسم الكامل للمدير.
  3. اسم المستخدم.
  4. البريد الإلكتروني.
  5. رقم الهاتف (اختياري).
  6. كلمة المرور.
  7. تأكيد كلمة المرور.
- تحققات محلية قبل الإرسال (تطابق كلمتي المرور، الحد الأدنى للأطوال، وصيغة البريد).
- مؤشر تحميل وحجب للزر أثناء المعالجة لمنع الضغط المتكرر.
- عند النجاح: حفظ الجلسة، عرض رسالة ترحيبية، والانتقال الفوري إلى `DashboardScreen` بحالة نظيفة للشبكة الجديدة.

### ج. شاشة الدخول (`lib/screens/temp_login_screen.dart`):
- إضافة رابط أسفل زر الدخول: `"ليس لديك حساب؟ أنشئ حساباً جديداً"` ينقل المستخدم مباشرة إلى `RegisterScreen`.

### د. اختبارات الواجهة والوحدة (`test/register_test.dart`):
- اختبار استدعاء `ApiClient.registerTenant` وتخزين التوكن.
- اختبار معالجة أخطاء 409 و 400.
- اختبار رسم حقول نموذج التسجيل.
- اختبار إظهار رسائل التحقق عند فراغ الحقول أو عدم تطابق كلمتي المرور.
- اختبار إتمام التسجيل والانتقال للداشبورد.
- اختبار رابط الانتقال من شاشة الدخول لشاشة التسجيل.
